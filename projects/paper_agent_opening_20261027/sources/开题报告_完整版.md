中文摘要

针对科研文献数量快速增长、综述撰写依赖人工且引用难以核验的问题，本项目拟设计并实现一个基于 CrewAI 的多智能体协同文献综述生成系统。系统以自然语言研究主题为输入，由协调、检索、分析、对比、撰写和引用校验智能体共同完成检索规划、论文筛选、方法抽取、演进脉络分析与结构化写作。系统采用面向科研文本的混合 RAG 策略：对 arXiv、PubMed 等来源的文献进行元数据规范化、章节感知切分，结合 BM25 与稠密向量检索、重排序和证据定位，将报告中的关键声明绑定到可回溯的原文证据。项目还将设计基于有向无环任务图的任务分解、结构化产物交换和冲突消解机制，避免多智能体自由对话导致的状态漂移与错误累积。在工程实现上，系统将提供 Web 交互原型，支持检索条件配置、生成进度监控、证据查看、报告编辑与多格式导出。评测将在检索增强生成、大语言模型多智能体系统、软件漏洞检测三个计算机子方向开展，与单智能体、无 RAG 等基线比较，重点考察引用准确性、证据可追溯性、内容覆盖度、结构完整性和专家满意度。预期形成可运行系统、评测工具、技术报告和可复现实验材料，为可信科研文献辅助工具提供可借鉴的工程方案。

English Abstract

To address the rapid growth of scientific literature and the difficulty of producing reviews with verifiable citations, this project designs and implements a CrewAI\-based multi\-agent system for intelligent literature review generation. Given a natural\-language research topic, a coordinator, retrieval, analysis, comparison, writing, and citation\-verification agents collaborate on search planning, paper screening, method extraction, research\-evolution analysis, and structured writing. The system applies a scientific\-text\-oriented hybrid RAG strategy: it normalizes metadata from sources such as arXiv and PubMed, performs section\-aware chunking, combines BM25 and dense retrieval, reranks candidate evidence, and binds key claims in the report to stable source snippets and locators. A directed acyclic task graph, typed artifact exchange, and conflict\-resolution mechanism are designed to avoid state drift and error accumulation in free\-form multi\-agent conversations. The engineering work includes a web prototype that supports constraint configuration, progress monitoring, evidence inspection, report editing, and multi\-format export. Evaluation will cover three computer\-science subfields: retrieval\-augmented generation, LLM\-based multi\-agent systems, and software vulnerability detection. It will compare the proposed system with single\-agent and no\-RAG baselines using citation precision, evidence traceability, content coverage, structural completeness, expert satisfaction, latency, and cost. The expected outcomes are a deployable prototype, evaluation tooling, a technical report, and reproducible experimental materials that provide an engineering reference for trustworthy research assistants.

科研文献的产出速度已经超过个人持续跟踪的能力。研究者在开展一个新课题时，通常需要经历主题拆解、数据库检索、论文筛选、方法抽取、结果对比和综述写作等环节；这些环节既依赖领域知识，也包含大量可重复但耗时的手工操作。传统综述往往由专家在数月内完成，普通课程项目或初入领域的研究者则容易受到检索遗漏、分类标准不一致和引用过期等问题的影响。随着预印本数量增加，单一数据库和一次性检索更难覆盖一个方向的主要工作，综述过程的透明性和可复现性也因此变得重要。

大语言模型（Large Language Model, LLM）为文献阅读和写作提供了新的自动化手段，但直接使用生成式模型存在两类核心风险：一是模型可能生成没有来源支撑的结论；二是长上下文中的关键信息容易被忽略或混淆\[11\]。检索增强生成（Retrieval\-Augmented Generation, RAG）通过先检索外部知识、再将证据放入生成上下文，为提高事实性和可溯源性提供了可行路径\[1\]\[2\]。与此同时，多智能体系统把复杂任务拆分为多个具有明确角色的子任务，使检索、分析、比较和写作可以由不同的智能体承担，并通过协作完成单智能体难以稳定处理的流程\[4\]\[5\]。因此，将 CrewAI 的多智能体编排能力与面向科研文本的 RAG 结合起来，构建一个可追溯、可评测的文献综述生成系统，具有明确的研究和工程价值。

2\.2 研究问题与意义

本项目关注的核心问题不是“让模型一次写出一篇文章”，而是“如何让一个多智能体系统在有限时间与预算内，稳定地产出覆盖关键工作、结构清晰且引用可核验的文献综述”。围绕这一问题，需要同时回答任务如何分解、证据如何检索、智能体结果如何融合、错误如何发现以及质量如何评测等子问题。现有系统往往强调生成结果的表面流畅性，却缺少对证据链、冲突观点和失败恢复的工程化处理；本项目试图把综述生成从一次性提示词调用转化为可观测、可回滚的工作流。

从理论角度看，本项目有助于探索 LLM 多智能体在长流程知识工作中的任务分解与结果融合方法，特别是结构化产物交换、证据约束生成和冲突消解对系统可靠性的影响。从应用角度看，系统可以降低研究者完成初步文献调研的时间成本，帮助课程学习者快速建立领域地图，并为课题组内部的知识管理提供可复用工具。相比只追求生成速度的“自动写作”工具，强调引用准确性和可复现性的系统更适合科研场景，也更容易被导师、审稿人和领域专家接受。

2\.3 国内外研究现状

2\.3.1 检索增强生成

RAG 的基本思想是在生成前检索与问题相关的外部文档，并把检索结果作为条件上下文。Lewis 等提出的 RAG 将参数化语言模型与非参数化文档索引结合，在开放域问答等知识密集型任务上验证了外部检索的价值\[1\]。此后，研究重点逐渐从“是否检索”转向“何时检索、检索什么、如何验证”。Gao 等的综述从检索、生成和增强三个层面梳理了 RAG 的技术路线\[2\]；Huang 和 Huang 进一步从文本生成角度总结了稠密检索、重排序、上下文压缩和评估方法\[3\]。Self\-RAG 通过让模型判断是否需要检索并对生成内容进行自我反思，说明了生成过程中的动态控制价值\[9\]。

在科学研究场景中，RAG 面临的困难比通用问答更突出。论文包含摘要、方法、实验设置、结果表格和限制讨论等多个层次，简单按固定长度切分会破坏论证结构；不同论文的实验条件和评价指标也不一致，不能仅凭相似度把结论拼接在一起。PaperQA 等工作尝试将检索、引用和科学问答结合，说明面向论文的检索需要同时考虑文本片段、来源元数据和可验证性\[14\]。本项目将采用“元数据过滤 \+ 混合检索 \+ 重排序 \+ 证据定位”的组合策略，并把引用校验从写作后的附加步骤提升为生成流程中的约束条件。

2\.3.2 大语言模型多智能体协作

LLM 多智能体系统通常通过角色设定、消息传递和任务分工，把复杂目标拆解为多个可管理的子任务。AutoGen 提供了多智能体对话与工具调用的通用框架\[5\]；MetaGPT 将标准作业程序引入多智能体协作，强调结构化中间产物对复杂任务的作用\[6\]；ChatDev 则通过角色分工和通信机制完成软件开发生命周期中的多项任务\[7\]。这些工作说明，多智能体的优势不仅来自“更多模型”，更来自角色边界、任务契约和可检查的中间结果。

不过，多智能体协作也会带来新的工程问题。自由对话容易导致上下文膨胀、职责漂移和错误级联；不同智能体可能重复检索或给出相互冲突的结论；在长流程中，如果没有统一的产物格式和状态管理，系统很难定位失败发生在哪一步\[4\]。CrewAI 以角色、目标和任务为核心抽象，支持顺序或层级式协作，适合快速搭建原型；但要把 CrewAI 用于科研写作，仍需要额外的任务图、证据库、结构化 schema 和校验器。本项目因此不把智能体之间的自然语言聊天作为唯一协作方式，而是采用“角色 \+ 任务 \+ 结构化产物”的混合编排。

2\.3.3 自动文献综述与科研助手

自动综述是 LLM 科研辅助中的代表性任务。LitLLM 将文献检索、摘要和综述草稿生成组织为工具链，强调以来源文献为基础的写作流程\[15\]；AutoSurvey 通过检索、组织大纲、分段生成和迭代修订等步骤，探索了大规模综述的自动生成方法\[16\]；Agent Laboratory 进一步把文献综述、实验和报告写作纳入研究助理式工作流\[17\]。这些系统证明了端到端自动综述的可行性，也暴露出一些共性不足：引用往往停留在文献级别，缺少“声明—证据—定位”的细粒度绑定；生成过程的可观测性有限；对不同子领域的评测还不够系统。

2\.3.4 国内相关研究概况

国内高校和研究机构在 LLM 智能体、代码智能和自动综述方向已有较多工作。ChatDev、MetaGPT 和 AutoSurvey 等代表性研究中都有国内团队参与，研究重点从角色协作扩展到结构化任务规划、软件工程流程和长文本组织\[6\]\[7\]\[16\]。产业界也出现了面向检索、知识库问答和报告生成的工具，但多数产品更强调交互体验和通用写作，对科研文本的章节结构、实验条件、引用定位和冲突观点处理仍不充分。总体来看，国内研究与国外研究几乎同步，真正缺少的是把多智能体、RAG 和可验证评测整合起来的开源工程原型。

2\.4 现有不足与发展趋势

现有自动综述系统的主要不足可以归纳为四点。第一，引用粒度偏粗。系统经常在段落末尾列出若干参考文献，但读者无法判断某一条具体结论由哪一篇论文、哪一段原文支持。第二，任务融合机制偏弱。多智能体系统更多依赖对话历史传递信息，缺少统一的证据对象、版本化产物和冲突处理规则。第三，评测范围有限。很多工作只在单一领域或少量主题上比较生成文本的流畅度，缺少对引用可靠性、覆盖度和跨领域泛化的联合评估。第四，工程闭环不完整。部分研究停留在离线脚本或演示页面，尚未覆盖任务恢复、权限控制、导出、成本监控和用户编辑等实际需求。

未来趋势是从“文本生成”走向“证据驱动的知识工作流”：检索、分析、比较、写作和验证将成为可观测的流水线；智能体之间将通过结构化对象交换信息；人类可以在关键节点进行审阅和纠错；评测将从单一 BLEU/ROUGE 等文本相似度指标转向引用准确率、事实一致性、覆盖度、专家评分和成本效率的组合指标\[12\]\[13\]\[18\]。本项目正是沿着这一趋势，设计面向科研文献的多智能体协作与混合 RAG 方案。

2\.5 调研方法与文献筛选

本阶段采用范围式文献调研与滚雪球检索相结合的方法。检索范围以 2020—2026 年的 arXiv、Crossref、ACL Anthology、NeurIPS/ICLR/ACL 等会议论文和 CrewAI 官方文档为主，关键词包括 retrieval\-augmented generation、multi\-agent LLM、automated literature review、scientific document understanding、citation verification、agent evaluation 等。筛选时优先保留与 RAG、多智能体协作、自动综述和科研问答直接相关的工作；对于基础方法，补充检索其原始论文和权威综述；对于新近预印本，重点关注是否提供可复现实验、开源代码或被后续工作引用。

调研过程按“问题—方法—证据—局限”四列整理文献：先记录研究问题和任务设置，再提取检索/生成/编排方法，随后核对实验数据、指标和结论，最后标注局限及与本项目的差异。该过程不是一次性穷举，而是随系统原型和评测结果迭代补充。当前调研的结论是：RAG 和多智能体分别有较成熟的技术基础，但两者的工程化整合、细粒度引用验证和跨子领域评测仍有明显空白，适合作为软件工程实验项目的切入点。

2\.6 选题的先进性与实用性

本选题的先进性体现在三个层面。其一，把多智能体协作从“角色对话”推进到“任务图 \+ 结构化产物 \+ 共享证据库”的工程模式，使每个阶段都有明确输入、输出和验收条件。其二，将混合检索、重排序、证据定位和引用校验组合为面向科研文本的 RAG 流水线，要求关键声明在生成时绑定 evidenceId，而不是在写作后机械补参考文献。其三，设计跨三个计算机子方向的评测方案，同时考察质量、引用、时延和成本，避免只用单一文本指标判断系统优劣。

实用性体现在系统面向真实的文献调研流程：用户可以输入自然语言主题，选择时间范围和数据源，查看生成进度，打开任意引用查看原文片段，编辑报告并导出 DOCX、PDF 或 Markdown。系统不替代研究者做最终判断，而是把重复的检索、整理和初稿搭建工作自动化，把人的精力集中到问题定义、证据审查和观点提炼上。对于课程项目而言，系统也提供了从需求分析、UML 建模、后端服务、前端交互到质量评测的完整软件工程实践。

2\.7 技术难点与工作量

本项目的技术难点主要来自五个方面。第一，学术数据接入存在格式差异和访问限制，需要处理 API 限流、分页、元数据缺失以及开放全文与摘要的边界。第二，论文解析需要保留章节、页码、表格和公式等结构信息，否则证据定位会失真。第三，混合检索和重排序需要在召回率、上下文长度和成本之间权衡，长上下文中的“中间信息丢失”会直接影响生成质量\[11\]。第四，多智能体错误会沿任务链传播，必须通过 schema 校验、置信度阈值、重试和人工复核控制风险。第五，综述质量具有主观性，需要设计可操作的评价量表、盲评流程和评分者一致性检验。

工作量估计包括：文献与需求调研约 3 周；系统架构、数据模型和 UML 设计约 2 周；数据接入、解析和 RAG 流水线约 6 周；CrewAI 编排、任务图、融合与校验约 5 周；Web 前后端与部署约 4 周；三领域评测、消融实验和报告撰写约 4 周。整体按 24 周安排，其中预留约 2 周用于联调、缺陷修复和答辩准备。项目工作量与一名本科生/研究生课程项目的周期基本匹配，但要求团队在数据治理和评测设计上投入足够精力。

三、课题内容及具体方案

3\.1 课题内容

3\.1.1 研究目标

本项目的总体目标是：面向科研文献综述这一长流程知识任务，设计并实现一个基于 CrewAI 的多智能体协同系统，使系统能够根据用户输入的自然语言主题，自动完成文献检索、内容分析、方法对比、结构化写作和引用校验，并通过 Web 应用提供可交互、可追溯、可导出的综述生成服务。系统不仅要在演示场景中生成流畅文本，还要在证据可核验性、任务可恢复性和跨子领域评测上达到课程项目可验证的质量水平。

具体目标包括：（1）建立至少包含检索、分析、对比、撰写和引用校验的多智能体角色体系，并明确每个角色的输入、输出和失败处理方式；（2）实现一种面向科研文本的混合 RAG 策略，覆盖元数据规范化、章节感知切分、BM25 与稠密检索、重排序、证据定位和引用绑定；（3）设计任务分解与结果融合机制，使多智能体协作从自由对话转变为可观测的任务图执行；（4）完成端到端 Web 原型，支持主题配置、过程监控、证据查看、报告编辑和多格式导出；（5）在三个计算机子方向上完成与单智能体、无 RAG 等基线的对比实验，形成技术报告和可复现材料。

3\.1.2 研究问题

围绕总体目标，本项目将以下研究问题作为设计与评测的主线。

__RQ1 __如何把文献综述任务分解为具有明确输入、输出和验收条件的智能体任务，并在任务失败时进行恢复？

__RQ2 __面向科研论文的混合 RAG 策略应如何组合元数据过滤、稀疏检索、稠密检索和重排序，才能提高引用准确性和证据覆盖率？

__RQ3 __如何融合检索、分析、对比和写作智能体的结构化产物，并在冲突时保留不同观点而不是强行给出单一结论？

__RQ4 __在检索增强生成、LLM 多智能体系统、软件漏洞检测三个子方向上，系统的质量、时延和成本如何权衡？

__RQ5 __如何把上述方法落地为可操作、可观测、可回滚的 Web 应用，并满足课程项目的工程规范？

3\.1.3 研究范围与边界

系统首期面向英文科研论文的检索与中英文综述生成，数据源优先接入 arXiv 和 PubMed，辅以 Crossref 等元数据服务。单次任务的候选论文规模控制在 40—80 篇，经过筛选后纳入 20—40 篇；报告长度可配置为 3000—8000 字。系统覆盖研究背景、主流方法分类、技术演进、代表性工作比较、开放问题和参考文献等章节，但不替代领域专家对研究价值的判断，也不承诺自动发现所有相关文献。对于无法获得开放全文的论文，系统只使用摘要和公开元数据，并在报告中明确标注证据范围。

系统采用人机协同原则：用户可以调整检索条件、删除不相关论文、编辑报告并查看引用证据；系统应保留每次生成使用的模型、提示词、检索参数和语料快照，以支持复现。由于大语言模型可能产生错误，最终报告在提交或发表前必须经过人工审查。项目不存储用户未授权的私人文献，不绕过数据库访问控制，不把受版权保护的全文重新分发。

3\.1.4 主要研究内容

主要研究内容包括五个部分：其一，多源学术数据接入与论文规范化；其二，面向科研文本的混合检索与证据库；其三，基于 CrewAI 的角色智能体与任务图编排；其四，结构化结果融合、声明—证据绑定和引用校验；其五，Web 原型与三领域评测。五个部分相互依赖：数据质量决定检索上限，检索质量决定分析依据，分析产物决定写作质量，引用校验决定可信度，评测结果反过来驱动任务分解和提示策略的迭代。

3\.3 系统概要设计

3\.3.1 设计原则

系统设计遵循五项原则。第一，证据优先：综述中的关键声明必须关联证据对象，不能只依赖模型记忆。第二，结构化协作：智能体之间传递带类型的产物，而不是无限增长的聊天记录。第三，确定性与灵活性结合：数据接入、去重、评分和校验由确定性代码完成，开放式归纳和写作交给 LLM。第四，人类可介入：检索条件、论文筛选、证据查看和报告编辑均保留人工操作入口。第五，可复现与可扩展：模型、提示词、检索参数和语料范围写入任务记录，数据源和模型通过适配器替换。

3\.3.2 总体架构

系统采用分层架构，如图 2 所示。表现层提供主题输入、进度、报告和证据面板；应用服务层负责 REST API、任务调度和 CrewAI 工作流编排；智能体层包含协调、检索、分析、对比、撰写和引用校验六类角色；RAG 与数据层负责混合检索、重排序、证据库、向量索引、关系数据库和对象存储；外部服务层包括 arXiv、PubMed 和可替换的 LLM 服务。Web 前端不直接访问模型密钥，所有外部调用由后端 LLM 网关统一管理。

3\.3.3 多智能体角色与 CrewAI 编排

系统使用 CrewAI 的 Agent、Task 和 Crew 抽象表达角色和目标，但不把整个系统简化为一次 crew.kickoff()。数据接入、任务状态、重试、预算和持久化由应用层控制；CrewAI 负责在受控的上下文中执行智能体任务并返回结构化结果。每个 Agent 配置角色、目标、工具和输出 schema；每个 Task 配置描述、期望输出、上下文依赖和最大重试次数；协调智能体根据主题生成任务图，编排器按依赖关系调度。对于可并行的逐论文分析任务，系统使用批次并行；对于需要全局视角的对比和写作任务，系统采用串行汇总。

3\.3.4 任务分解机制

任务分解采用“阶段—任务—产物”三层结构。阶段对应检索、分析、对比、写作和校验；任务是最小调度单元，具有唯一编号、依赖列表、输入引用、约束、输出 schema、优先级、超时和重试策略；产物是不可变的版本化对象，写入共享黑板（blackboard）后供下游引用。任务图是有向无环图（DAG），允许分析任务并行、写作任务按章节并行，但所有合并节点必须等待依赖完成。

| --- |

任务状态机为 CREATED → PLANNING → RETRIEVING → ANALYZING → COMPARING → DRAFTING → VERIFYING → COMPLETED；任一阶段可进入 FAILED 或 CANCELLED，重试时从最近检查点恢复而不是重新执行全部流程。协调器在每阶段检查 token 预算、论文覆盖率和证据数量；若覆盖率不足，则扩展检索而不是让写作智能体凭空补全。共享黑板只接受通过 schema 校验的产物，避免无效文本污染下游上下文。

3\.3.5 结果融合与冲突消解

结果融合分为五步：规范化、去重、聚类、冲突检测和证据约束写作。论文先去重（DOI/arXiv ID 精确匹配，标题\+作者\+年份模糊匹配），再按方法和任务聚类；分析产物按论文 ID 合并，缺失字段保留为空而不是推测。对比产物将相似性、差异、时间线和矛盾分别记录；当不同论文对同一问题给出冲突结论时，系统保留双方观点、实验条件与证据，不强行投票生成单一结论。

为支持可解释融合，系统为证据计算可配置的质量分：Q(e) = 0.30×Relevance(e) \+ 0.25×Credibility(e) \+ 0.25×Verifiability(e) \+ 0.20×Recency(e)。其中 Relevance 来自检索/重排序分数，Credibility 考虑来源类型和同行评审状态，Verifiability 考虑是否存在原文定位，Recency 按时间衰减。权重在开发阶段仅作为初始值，最终通过验证集校准。声明 c 的证据支持度定义为 Support(c) = Σ w\_e×Entail(e,c) / Σ w\_e；初始设计以 0.75 为自动通过阈值，0.50—0.75 进入人工复核，低于 0.50 则拒绝写入正文。

| 产物 | 生产者 | 关键字段 | 消费者 |
| --- | --- | --- | --- |
| PlanArtifact | 协调智能体 | subqueries、filters、budget、task_dag | 检索/编排器 |

合并策略强调“可追溯的保守写作”。如果两篇论文的实验条件不同，系统不会直接给出“方法 A 优于方法 B”的结论，而是写成“在数据集 D、指标 M 和设置 S 下，A 报告了较高结果；B 的实验条件为……”。对于只有摘要证据的论文，系统降低其可信度并标注“仅摘要证据”。这类保守表达会牺牲部分文风流畅度，但能减少把不同实验口径混为一谈的风险。

3\.3.6 面向科研文本的 RAG 策略

本项目的 RAG 不是简单的“向量检索 \+ 拼接提示词”，而是由数据接入、结构化切分、混合召回、重排序、证据绑定和引用校验组成的流水线。系统优先使用开放获取的全文；无法获得全文时，仅使用摘要、标题和公开元数据，并在证据对象中记录 evidence\_scope。论文按摘要、引言、方法、实验、结果、局限和结论等章节切分，保留页码、段落和表格标题等定位信息。该设计使引用不仅能看到“出自哪篇论文”，还能定位到“哪一节、哪一段、哪张表”。

__表 10  科研文本 RAG 流水线设计__

| 阶段 | 设计要点 | 关键参数/策略 | 输出 |
| --- | --- | --- | --- |
| 数据接入 | arXiv/PubMed/Crossref 适配器，记录来源、许可和抓取时间 | 分页、退避、缓存；开放全文优先 | 标准化 Paper 元数据 |
| 清洗去重 | DOI/arXiv ID 精确匹配；标题+作者+年份模糊匹配 | 版本合并；预印本与正式版标注 | 去重后的论文集合 |
| 章节切分 | 保留章节、页码、段落和表格标题 | 500—900 tokens；100—150 overlap | DocumentChunk + locator |
| 索引构建 | BM25 倒排索引 + 稠密向量索引 | bge-m3 或可替换嵌入模型；pgvector | 可检索证据库 |
| 混合召回 | 查询扩展后并行执行稀疏/稠密检索 | 元数据过滤：年份、来源、类型 | Top-k 证据候选 |
| 重排序 | 交叉编码器或 LLM 重排，兼顾相关性与多样性 | 召回 50 → 重排 12；按论文去冗余 | 证据上下文 |
| 生成与校验 | 写作时绑定 evidenceId；校验 entailment 和 locator | 支持度阈值；失败定向重试 | 可追溯报告 |
| 增量更新 | 按主题保存语料快照；支持重新索引 | 定时/手动刷新；版本哈希 | 可复现语料版本 |

混合召回阶段，系统对每个子查询分别取 BM25 Top\-k 和稠密向量 Top\-k，再以加权分数合并：Score(q,e) = λ×BM25(q,e) \+ (1−λ)×cos(Emb(q),Emb(e))，λ 在验证集上调。候选证据经过重排序后，还要执行论文级和章节级去冗余，避免上下文被同一篇论文的重复片段占满。上下文组装采用“证据卡片”格式，每张卡片包含 evidenceId、论文标题、年份、章节、原文片段和定位；写作智能体只能引用卡片中的 evidenceId。若论文较长且证据分散，系统采用多轮检索而不是一次性塞入全部全文\[11\]。

3\.3.11 异常处理、可观测性与安全

异常处理遵循“记录—分类—重试—降级—人工介入”的顺序。数据源超时或限流时，系统按指数退避重试，并在覆盖率不足时提示更换数据源；检索结果过少时，扩大时间范围或使用同义词；智能体输出不符合 schema 时，先进行一次修复提示，仍失败则标记任务失败而不把无效文本传给下游；引用校验失败时，返回 unsupportedClaims 并在报告中保留问题标记。

可观测性方面，每个任务记录 trace\_id、阶段耗时、模型/token 使用量、检索命中数、失败原因和重试次数；前端展示用户可理解的进度，研发侧可通过结构化日志定位问题。安全方面，落实 API 鉴权、项目级 RBAC、输入长度和速率限制、日志脱敏、密钥隔离和导出权限检查；对上传文献和个人数据按最小必要原则保存，并提供项目删除功能。

3\.4.3 三领域评测设计

为满足“在 2—3 个计算机领域子方向上评估综述质量”的要求，项目选择检索增强生成、LLM 多智能体系统和软件漏洞检测三个子方向。三者分别代表“方法/系统型主题”“协作机制型主题”和“应用安全型主题”，能够检验系统在不同论文结构、评价指标和术语体系下的适应能力。每个方向选取 3 个代表性主题，每个主题准备 1 份专家关键点清单和 1 组引用核验样本；候选论文由系统检索，人工只负责最终核验，不提前把答案提供给系统。

__表 17  三个计算机子方向的评测设置__

| 子方向 | 示例主题 | 评测重点 | 基线/消融 |
| --- | --- | --- | --- |
| 检索增强生成 | RAG 的忠实性评估与混合检索 | 检索覆盖、证据绑定、引用精度 | Direct LLM；Single-agent + RAG |
| LLM 多智能体系统 | 多智能体任务分解与协作机制 | 方法分类、协作机制对比、演进脉络 | Multi-agent without RAG；Ours |
| 软件漏洞检测 | 基于深度学习的漏洞检测与数据集偏差 | 实验条件对比、数据集/指标抽取、局限识别 | Single-agent + RAG；Ours without verifier |

评测指标分为五组。检索组：Recall@20、nDCG@10、来源覆盖率和去重准确率；引用组：引用精度（被支持引用数/引用总数）、引用召回（有证据声明数/应引用声明数）、定位准确率和关键声明证据绑定率；内容组：关键方法覆盖率、方法分类一致性、演进脉络完整性和局限识别率；写作组：结构完整性、连贯性、批判性和可读性；效率组：端到端时延、token 成本和任务成功率。引用精度和证据绑定率作为一等指标，不能仅用文本相似度代替。

自动评测采用 RAGAS/ARES 等框架提供的忠实性、答案相关性和上下文指标作为辅助\[12\]\[13\]，同时开发面向综述的规则检查：每条关键声明是否存在 evidenceId、引用是否能定位、数字/数据集/指标是否与原文一致。人工评测由 3 名具备相关背景的评分者独立完成，使用 5 分制量表（1=明显错误，5=可直接作为研究材料），随机盲评系统输出与基线输出。评分前进行样例校准，报告 Krippendorff's α 以检查一致性；目标 α≥0.70，若低于阈值则修订评分量表并重新抽检\[22\]。对主要指标采用配对比较或 Wilcoxon 符号秩检验，报告效应量和置信区间。

3\.5.2 项目特色与创新点

（1）角色—任务—产物三层编排。项目不只设置多个角色，还为每个任务定义契约、依赖和验收条件，用任务图取代无界对话，适合长流程科研写作。

（2）证据优先的混合 RAG。系统将元数据过滤、BM25、稠密检索、重排序和章节定位组合起来，并把 claim\-evidence 绑定作为写作约束，而不是事后补引用。

（3）可解释的结果融合。分析、对比和写作产物统一进入共享黑板；冲突观点保留实验条件和来源，不追求表面一致的“唯一答案”。

（4）跨三领域、可重复的评测。除引用与覆盖指标外，同时测量时延和成本，使用人工盲评与评分者一致性检验，避免只展示“看起来不错”的样例。

（5）完整的 Web 工程闭环。系统覆盖输入配置、异步任务、进度推送、证据查看、报告编辑、版本管理和多格式导出，可作为后续科研知识管理工具的工程底座。

上述设计把多智能体协作、混合 RAG、领域数据建模和 Web 工程连接为一个闭环。后续实现将优先保证证据链完整和任务可恢复，再优化写作风格与界面细节；三领域评测结果将用于校准任务分解粒度、检索参数和融合阈值。
